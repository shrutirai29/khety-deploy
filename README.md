## 🧭 The Problem

<table>
<tr>
<td width="50%" valign="top">

Farmers in India routinely deal with:

- 🧪 Fake / counterfeit fertilizers and seeds
- 💰 Unfair market prices from middlemen
- 🌾 No easy access to soil & crop guidance
- 🧩 Fragmented tools — one app for weather, another for selling, none for diagnosis

</td>
<td width="50%" valign="top" align="center">

```yaml
solution: "Khety"
approach: >
  One role-based platform for farmers
  and buyers — direct trade, direct
  chat, and an AI model that reads
  crop-leaf photos for disease.
roles:
  - Farmer
  - Owner (Buyer)
```

```
                    ┌───────────────────────┐
                    │   React Frontend       │
                    │  (khety-frontend)      │
                    │  Render Static Site    │
                    └──────────┬────────────┘
                               │  REACT_APP_API_URL
                               ▼
                    ┌───────────────────────┐
                    │  Node/Express Backend  │
                    │  (khety-backend)       │
                    │                        │
                    │  /api/auth             │
                    │  /api/crops            │
                    │  /api/products         │
                    │  /api/upload-image     │
                    │  /api/save-prediction  │
                    │  /api/dashboard/*      │
                    └──────┬─────────┬──────┘
                           │         │
              ┌────────────┘         └─────────────┐
              ▼                                     ▼
     ┌────────────────┐                   ┌──────────────────┐
     │   MongoDB       │                   │   Cloudinary      │
     │  Users, Crops,  │                   │  (image hosting)  │
     │  Products,      │                   └──────────────────┘
     │  Predictions,   │
     │  Orders         │        REACT_APP_ML_API_URL (direct from frontend)
     └────────────────┘                   ┌──────────────────┐
                                           │  Flask ML Service │
                                           │  (khety-ml)       │
                                           │  CNN model        │
                                           │  /predict         │
                                           └──────────────────┘
```

> 💡 The frontend calls the ML service **directly** for predictions, then sends the result to the Node backend to persist it — keeping heavy image-inference off the main API server.

## 🔍 Feature Breakdown

<details open>
<summary><b>🔐 1. Auth & Accounts</b></summary>
<br/>

Signup collects role (farmer/owner), location, and optional profile detail (farm size, primary crops, experience level, bio). Passwords are hashed with **scrypt** (salted, timing-safe verification) and legacy plaintext passwords are auto-upgraded on next login. Email OTP verification runs before registration completes. Forgot-password issues a time-limited reset token emailed via Nodemailer; if mail credentials aren't configured, the reset link is logged server-side instead of silently failing. All auth routes are rate-limited (20 requests / 15 minutes per IP+path).

</details>

<details>
<summary><b>🌽 2. Crop Marketplace (Farmer ↔ Owner)</b></summary>
<br/>

Farmers create listings restricted to their own `farmerId`. Owners send a request (chat or purchase intent) on a listing, which either creates a new `interestedBuyers` entry or updates an existing one. Each request carries its own `chatMessages` thread. Status moves through `pending → accepted → confirmed`, with independent `farmerConfirmed`/`ownerConfirmed` flags — a request is only truly `confirmed` when both flags are true. Changing a fully confirmed request back requires a `reopenReason`, and the system logs who reopened it and when.

</details>

<details>
<summary><b>🔬 3. Plant Disease Detection</b></summary>
<br/>

Users upload a leaf image → it's uploaded to Cloudinary → sent to the Flask ML service, which resizes it to 224×224, runs it through a pretrained CNN, and returns one of 15 disease/healthy classes (pepper, potato, and tomato varieties) with a confidence score. The result and a structured report (problem/cause/symptoms/damage/solution) are saved and viewable later in history or as a standalone report page.

</details>

<details>
<summary><b>🛒 4. Supply Marketplace</b></summary>
<br/>

A separate, admin-managed product catalog (seeds, fertilizers, compost, pesticides) is auto-seeded on backend startup with 8 curated starter products, each carrying SKU, stock, unit label, and category — independent from the farmer-listed crop marketplace.

</details>

<details>
<summary><b>📊 5. Dashboards</b></summary>
<br/>

`GET /api/dashboard/summary` returns role-specific metrics:
- **Farmer** — total scans, healthy vs. flagged scans, total/active listings, total/pending buyer requests, plus a merged activity feed sorted by recency.
- **Owner** — total listings visible, count of their own requests, pending requests, and active negotiations.

</details>

<details>
<summary><b>🎙️ 6. Accessibility — Voice & Language</b></summary>
<br/>

`VoiceNavigator` uses the browser's Speech Recognition API to let users navigate by voice, with locale mapping for English, Hindi, Bengali, Telugu, Marathi, Tamil, Urdu, Gujarati, Kannada, Malayalam, Punjabi, Odia, Assamese, and several international languages. `Translator` provides a similar language switcher for on-page translation.

</details>

## 🗄️ Database Schema

<div align="center">

| Model | Purpose | Key Fields |
|---|---|---|
| 👤 **User** | Farmer/owner account | `role`, `location`, `farmSize`, `primaryCrops`, `experienceLevel`, `accountStatus` |
| 🌽 **Crop** | A farmer's listing | `name`, `price`, `quantity`, `unit`, `availability`, `listingStatus`, `interestedBuyers[]` |

## 🔌 API Reference

### 🔐 Auth — `/api/auth`

| Method | Route | Description |
|:---:|---|---|
| `POST` | `/send-otp` | Email a signup OTP |
| `POST` | `/verify-otp` | Verify OTP before registration |
| `POST` | `/register` | Create account (farmer/owner) |
| `POST` | `/login` | Authenticate, returns token + user |
| `POST` | `/forgot-password` | Email a password reset link |
| `POST` | `/reset-password` | Reset password via token |
| `GET` | `/me` | Get current profile |
| `PUT` | `/me` | Update profile |
| `PATCH` | `/deactivate` | Deactivate account |

### 🌽 Crops — top-level

| Method | Route | Description |
|:---:|---|---|
| `GET` | `/api/crops` | List crops, filterable by `farmerId` or `ownerId` |
| `POST` | `/api/crops` | Create a crop listing (farmer only) |
| `POST` | `/api/crops/:id/request` | Owner sends/updates a purchase request |
| `PATCH` | `/api/crops/:cropId/request/:ownerId/status` | Update request status / confirm deal |
| `POST` | `/api/crops/:cropId/request/:ownerId/messages` | Post a chat message on a request |
| `POST` | `/api/crop-interest/:id` | Legacy "show interest" endpoint |

### 🔬 Detection & Uploads

| Method | Route | Description |
|:---:|---|---|
| `POST` | `/api/upload-image` | Upload image to Cloudinary |
| `POST` | `/api/save-prediction` | Save a disease-scan result |

| `GET` | `/api/prediction/:id` | Get a single scan report |

## 🤖 ML Service

A standalone Flask app (`khety-ml/app.py`) that:

1. Loads a Keras CNN (`plant_disease_model.h5`) on startup — downloading it from a configured `MODEL_URL` (supports Google Drive links) if not already present locally.
2. Exposes `POST /predict`, accepting a multipart image file.
3. Resizes to 224×224, normalizes, and classifies into one of 15 classes:

<div align="center">

| Crop | Classes |
|---|---|
| 🫑 Pepper Bell | Bacterial Spot · Healthy |
| 🥔 Potato | Early Blight · Late Blight · Healthy |
| 🍅 Tomato | Target Spot · Mosaic Virus · Yellow Leaf Curl Virus · Bacterial Spot · Early Blight · Late Blight · Leaf Mold · Septoria Leaf Spot · Spider Mites · Healthy |

</div>

4. Returns `{ prediction, confidence }` as JSON.

### 1️⃣ Backend — `localhost:5000`

```bash
cd khety-backend
npm install
# create a .env with MONGODB_URI, AUTH_SECRET, etc. (see Environment Variables)
node index.js
```

### 2️⃣ ML Service — `localhost:5001`

```bash
cd khety-backend/khety-ml
pip install -r requirements.txt
# place plant_disease_model.h5 in this folder, or set MODEL_URL
python app.py
```

### 3️⃣ Frontend — `localhost:3000`

```bash
cd khety-frontend
npm install
# create a .env with REACT_APP_API_URL and REACT_APP_ML_API_URL
npm start
```

> On Windows, run all three at once from the repo root: `npm run start`

## ☁️ Deployment Notes

Deployed on **Render** as three separate services (frontend static site, backend web service, ML web service).

> ⚠️ **Before redeploying, know these:**
> - The ML model file (`plant_disease_model.h5`) is **not committed to git** — it's fetched at runtime via `MODEL_URL`, so that variable must be set before the ML service can start.
> - Cloudinary credentials currently live in `config/cloudinary.js` directly — rotate and move to environment variables before wider production use.
> - Real email delivery only kicks in when `MAIL_USER`, `MAIL_PASS`, and `MAIL_FROM` are all set; otherwise OTPs and reset links only appear in server logs.
> - Client-side routing requires rewrite rules on the static host so refreshing on `/login`, `/dashboard`, `/report/:id`, or `/reset-password/:token` doesn't 404.

A full pre-launch checklist covering auth, farmer/owner flows, marketplace, detection, and routing lives in [`deployment-checklist.md`](./deployment-checklist.md).
